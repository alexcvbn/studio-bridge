# D 필수 동작 최종 판정 (09회차 #36)

D 영역(자료 수신·원문·이전 수집본·중복 방지·백업 복원)이 09회차 코드 그대로 끝까지 동작하는지 판정합니다.
새 API·기능은 만들지 않습니다. **자동 판정**은 스크립트가 하고, **사람만 할 수 있는 확인**은 아래 표를 채웁니다.
결과는 실제로 해 본 것만 적고, 예시 데이터·실제 API·실제 Studio를 구분합니다.

## 1. 자동 판정 (한 번에)

```bash
cd server
uv run python scripts/check_final_d.py          # 끝나면 임시 폴더를 지움
uv run python scripts/check_final_d.py --keep   # 임시 폴더(DB·보드·백업·복원본·기록)를 남김
```

임시 DB·임시 보드 폴더로 API 서버·동기화 서버를 빈 포트에 직접 띄우고 끕니다. 실제 데이터는 쓰지 않습니다.
필요한 것: `uv`, Node.js, `sync` 폴더에서 `npm ci`.

| 단계 | 확인하는 것 |
| --- | --- |
| 1 | 원문 보내기 (한글·탭·CRLF·줄 끝 공백·빈 줄·이모지) → 201 |
| 2 | 같은 요청 재시도 차례로 3번 + 동시에 5번 → 모두 200 중복, 같은 ID, 수집본 1개 |
| 3 | 바꾼 코드를 새 request_id로 → 201, 같은 자료·새 수집본 |
| 4 | 현재/이전 원문 **바이트 단위** 일치 (수집본 기록·자료 상세·source_uid 조회) |
| 5 | 기능 연결·결정 5000→6000, Studio 문맥 조회, 보드에 자료·기능 카드와 메모 (실제 WebSocket) |
| 6 | 두 서버를 끄고 `backup_restore.py` 백업 → 새 폴더에 복원 → `verify` 12항목 (#32) |
| 7 | 원본·복원본 서버를 함께 띄워 `verify-api` (#32), `check_restore_features.py compare` (#31) |
| 8 | 복원본의 현재/이전 원문 바이트 일치, 복원본 동기화 서버에 붙어 읽은 보드가 백업 전과 같음 |

## 2. 사람이 하는 확인

### 2-1. 실제 Studio (D + A)

API 서버·동기화 서버·웹을 켜고, Studio 플러그인 서버 주소를 맞춘 뒤 진행합니다.

| # | 조작 | 기대 결과 | 실제 결과 | 통과 |
| --- | --- | --- | --- | --- |
| 1 | BossAI 스크립트 선택 → 코드 보내기 | 플러그인에 "완료"와 material_id·snapshot_id. 웹 자료함에 같은 원문 | | |
| 2 | API 서버를 끈 채 코드 보내기 → 실패 안내 확인 → 서버를 켜고 "같은 요청으로 다시 시도" | 실패 때 완료 표시 없음. 재시도 결과 "(이미 받은 요청)" 또는 새 저장 1건. 수집본이 2개로 늘지 않음 | | |
| 3 | 코드를 바꿔(예: 5000→6000) 다시 보내기 | 새 snapshot_id. 웹 수집본 기록에 현재 1개 + 이전 1개, 요청 ID가 서로 다름 | | |
| 4 | 웹에서 이전 수집본 열기 | "이전 수집본" 안내와 1번 원문이 탭·빈 줄까지 그대로 | | |
| 5 | 스크립트 이름을 바꿔 보내기 | 같은 자료(같은 material_id), 목록 이름만 새 이름 | | |
| 6 | 스크립트를 복제해 복제본 보내기 | 플러그인이 같은 source_uid 복제본을 안내하고 멈춤(A). 원본 자료에 섞이지 않음 | | |

### 2-2. 두 PC 전체 시나리오 (A·B·C·D 함께)

서버 PC 1대(공유 모드, 같은 팀 키)와 다른 PC 1대 이상. 순서는 `server/README.md`의 "두 컴퓨터 공유 실행".

| # | 조작 | 기대 결과 | 담당 | 실제 결과 | 통과 |
| --- | --- | --- | --- | --- | --- |
| 1 | 다른 PC의 Studio에서 코드 보내기 | 서버 PC 웹 자료함에 같은 원문 | A·D | | |
| 2 | 다른 PC 웹에서 기능 연결·결정 6000 | 서버 PC 웹과 Studio "관련 결정 읽기"에 같은 현재 결정 | C·A | | |
| 3 | 두 PC에서 보드 카드 추가·이동·메모 | 양쪽 보드가 같음 | B | | |
| 4 | 두 서버를 끄고 백업 → 시험 폴더 복원 → `verify` | 12/12 통과 | D | | |
| 5 | 복원본으로 다시 띄워 두 PC에서 보기 | 원문·이전 수집본·연결·결정·카드·메모가 같음 (BACKUP.md 확인표) | 전원 | | |

### 2-3. 제출 시연용 기준 자료 보관 (D)

1. 시연에 쓸 자료를 실제 화면으로 준비합니다 (BossAI 현재/이전 수집본, 기능·결정 5000→6000, 보드 카드·메모).
2. 두 서버를 끄고 백업합니다. 폴더 이름에 용도를 붙여 둡니다.

   ```bash
   uv run python scripts/backup_restore.py backup --out ../../studio-bridge-backups/demo-baseline
   ```

3. 바로 시험 폴더에 복원해 `verify`가 12/12인지 확인합니다. 이 백업은 시연 직전 같은 상태로 되돌릴 때 씁니다 (BACKUP.md 4절).
4. 백업 폴더(`manifest.json` 포함)는 저장소에 올리지 않고 팀이 정한 안전한 곳에 둡니다. 결정 문장·원문이 그대로 들어 있습니다.
5. 시연 전에 같은 백업을 복원해 화면이 같은지 다시 봅니다.

# A 필수 동작 최종 판정 (09회차 #33)

A 영역(플러그인 설치·연결·코드 보내기·관련 결정 읽기, 서버 접속·팀 키·재시작)이 09회차 코드 그대로 **다른 PC에서도** 동작하는지 판정합니다.
새 API·기능은 만들지 않습니다. **자동 판정**은 스크립트가 하고, **사람만 할 수 있는 확인**(실제 Studio, 서로 다른 두 PC, 담당자가 아닌 팀원)은 아래 표를 채웁니다.
결과는 실제로 해 본 것만 적고, 임시 데이터·실제 API·실제 Studio를 구분합니다. 팀 키는 이 문서·이슈·화면 녹화에 적지 않습니다.

## 2. 자동 판정 (한 번에)

```bash
cd server
uv run python scripts/check_final_a.py          # 127.0.0.1만, 끝나면 임시 폴더를 지움
uv run python scripts/check_final_a.py --lan    # 공유 모드 서버를 0.0.0.0에 열고 이 PC의 LAN 주소로도 검사
uv run python scripts/check_final_a.py --keep   # 임시 폴더(DB·서버 기록)를 남김
```

03~08회차에 만든 검사를 임시 DB·임시 팀 키·빈 포트의 서버에 차례로 실행합니다. 실제 DB와 실제 팀 키는 쓰지 않습니다. 필요한 것: `uv`.

| 단계 | 검사 | 보는 것 |
| --- | --- | --- |
| 1 | `check_restart` (#29) | 모든 제품 API의 키 없음·틀린 키·다른 프로젝트 거절, 서버를 껐다 켠 뒤 응답 전체가 같음, 복원본 DB, 다른 DB 경로 경고, 기록에 키 없음 |

## 3. 두 PC 전체 시나리오 — 담당자가 아닌 팀원이 조작

**조작하는 사람은 A(황재민)가 아닌 팀원**입니다. A는 서버 PC를 띄우고 옆에서 보기만 합니다. 막히면 그 화면 문구를 "실제 결과"에 그대로 적습니다.

### 3-0. 준비

서버 PC (A): `server/README.md`의 "두 컴퓨터 공유 실행" 순서로 API 서버·보드 동기화 서버·웹을 **같은 팀 키**로 띄웁니다. 시작 기록의 `다른 PC의 Studio 서버 주소`를 팀원에게 알리고, 팀 키는 메신저로 따로 보냅니다.

다른 PC (팀원): 저장소를 받아 `plugin/README.md`의 "설치"대로 `StudioBridge.lua`를 플러그인 폴더에 복사하고 Studio를 엽니다.

| 항목 | 값 (실제로 쓴 것) |
| --- | --- |
| 날짜 / 코드 버전 (`git rev-parse --short HEAD`, 두 PC 같아야 함) | |
| 서버 PC — 담당 / OS | |
| 다른 PC — 조작한 팀원 / OS / Studio 버전 | |
| 네트워크 (같은 Wi-Fi·핫스팟 등) | |

Studio를 열기 전에 다른 PC 터미널에서 연결만 먼저 봅니다. 읽기만 하고 아무것도 저장하지 않습니다. (Windows PowerShell은 `curl.exe`)

```bash
curl -s http://<서버 PC IP>:8000/api/health
curl -s http://<서버 PC IP>:8000/api/projects/studio-bridge/access
```

| 결과 | 뜻 | 다음 행동 |
| --- | --- | --- |
| 첫 줄 `{"status":"ok"}`, 둘째 줄 `team_key_required` | 서버에 닿고 공유 모드임 | Studio로 진행 |
| 응답 없음 (`curl: (7)` 또는 멈춤) | 주소·서버 꺼짐·서버 PC 방화벽 8000 | 서버 PC IP와 방화벽 확인. Studio 문제가 아님 |
| 둘째 줄 `local_only` | 서버를 팀 키 없이 `uvicorn --host 0.0.0.0`으로 띄움 | 서버 PC에서 팀 키를 주고 `uv run python -m app.serve`로 다시 실행 |
